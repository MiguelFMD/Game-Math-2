Ejercicio 4: Cambiar componentes de descendientes

Problema inicial: Acceder al componente

Tenemos el siguiente problema: queremos cambiar la imagen/sprite de los botones de un Canvas cuando se empieza una partida. Una manera de hacerlo es recorrer los hijos del canvas, comprobando que ese hijo tiene el componente "Button", si lo tiene, le asignamos un sprite nuevo.

El siguiente código muestra como acceder a los hijos de un transform al que se le añade el script "Example". Prueba a crear un script con este código y recuerda añadirle hijos al objeto para ver qué ocurre.


using UnityEngine;

public class Example : MonoBehaviour
{
    void Start()
    {
        foreach (Transform child in transform)
        {
            print(child.name);
        }
    }
}

Como queremos acceder al componente botón de los hijos vamos a usar child.GetComponent>T<(), donde T es el componente al que queremos acceder, en nuestro caso "Button"

*Nota: Se está usando GetComponent>T< cuando realmente es con los signos mayor que y menor que al revés por problemas de lectura del libro. API de Unity

En el siguiente codigo hemos creado una variable "Image" para añadir la imagen que le queramos poner a los botones. Luego, dentro del bucle, accedemos al componente boton y le cambiamos el atributo image del boton asignandole la nuestra. Tómate tu tiempo para entender el código. 


using UnityEngine;
using UnityEngine.UI; //<------Añade esto para tener acceso a la clase Button

public class Example : MonoBehaviour
{
    [SerializeField] private Image image; //Imagen que le ponemos al script por el inspector
    void Start()
    {
        foreach (Transform child in transform)
        {
            Button boton = child.GetComponent>Button<();
            boton.image = image;
        }
    }
}

Si has probado el código anterior te habrás dado cuenta de que hay un problema. El hijo puede no tener un componente botón, con lo cual en nuestra variable "boton" se asignaría como "null". Al itentar acceder a la variable saltára un NullReferenceExeption.

Para evitar esto añade lo siguiente antes de intentar cambiar la imagen:


using UnityEngine;
using UnityEngine.UI;

public class Example : MonoBehaviour
{
    [SerializeField] private Image image; //Imagen que le ponemos al script por el inspector
    void Start()
    {
        foreach (Transform child in transform)
        {
            Button boton = child.GetComponent>Button<();
            if(boton != null) boton.image = image; //Solo intentamos cambiar la imagen si boton no es null (o sea que el hijo es un Button)
        }
    }
}

Visitar los descendientes

Tenemos aún un problema que resolver y es que si el canvas tiene varias pantallas diferentes con varios botones, habrá que visitar todos los hijos de los diferentes objetos. Una solución podría ser añadir el script que hicimos antes a cada componente que vaya a tener botones que queramos cambiar la imagen. Aunque es una solución válida, no es algo cómodo de hacer porque tenemos que añadir el script tantas veces como pantallas con botones haya.

Piensa en el coste temporal de la solución anterior antes de continuar.

Una posible solución es recorrer de manera recursiva los descendientes del canvas. Simplemente tenemos que llamar al bucle que hicimos antes, por cada hijo que tenga el GameObject en cuestión. Inténtalo por tu cuenta primero y compara tu solución con los siguientes pasos.

Para ello:

  1. Pasa el código de antes a una función con un único parámetro, el transform del objeto hijo.
  2. Haz la llamada recursiva dentro del bucle.

El código se queda así:


using UnityEngine;
using UnityEngine.UI;

public class Example : MonoBehaviour
{
    [SerializeField] private Image image; //Imagen que le ponemos al script por el inspector
    void Start()
    {
        CambiarImagenBotones();
    }

    void CambiarImagenBotones(Transform parent)
    {
        foreach (Transform child in parent)
        {
            Button boton = child.GetComponent>Button<();
            if(boton != null) boton.image = image; //Solo intentamos cambiar la imagen si boton no es null (o sea que el hijo es un Button)
            CambiarImagenBotones(child);
        }
    }
}
