Ejercicio 1: Actualizar proyecto y entregar tarea

En un proyecto con un repositorio normal los colaboradores se bajan actualizaciones del proyecto (fecth & pull), y luego suben sus actualizaciones (push) para que el resto pueda trabajar con esos nuevos cambios.

En nuestro caso vamos a trabajar de manera diferente, el profesor subirá actualizaciones al proyecto, y tú, únicamente deberás bajarte los cambios. Cada ejercicio tendrá una entrega en el campus virtual la cual se deberá entregar de una forma concreta.

Este ejercicio sirve como práctica para saber cómo actualizar el proyecto (bajarte los cambios si hay) y subir las tareas de manera correcta.

1. Actualizar el proyecto

Antes de nada deberás haber acabado el ejercicio 0.

  • Abre GitHub Desktop y pulsa "Fetch origin". Esto comprobará si hay cambios que no te has bajado.
  • Si hay cambios que debes bajarte, el botón cambiará a "Pull origin". Púlsaslo y espera a que se bajen.
  • Ahora tu proyecto ya está actualizado y puedes trabajar con la última versión.
Recuerda los pasos

Estos pasos son importantes hacerlos antes de ponerte a trabajar en un respositorio, tanto para este como para tus siguientes proyectos que trabajes en equipo.

2. Trabajar en el proyecto

Para trabajar en el proyecto debes crear tu propia carpeta de trabajo en la siguiente ruta:

/Assets/ClassResources/Students

Ponle el siguiente formato de nombre:

ApellidosNombre

Ahora crea una estructura de carpetas, dentro de tu carpeta que acabas de crear de la siguiente manera:

  • /Assets/ClassResources/Students/ApellidosNombre/Scripts
  • /Assets/ClassResources/Students/ApellidosNombre/Scenes
  • /Assets/ClassResources/Students/ApellidosNombre/Prefabs

Siempre que vayas a trabajar en el proyecto debes trabajar únicamente dentro de tu carpeta. Todos los nuevos assets que crees o modifiques deben de estar ahí dentro.

Por ahora con esas carpetas tienes suficiente. Puedes crear más siempre y cuando sea dentro de tu carpeta

Tus carpetas se mantendrán guardadas en tu ordenador (en local) pero solo las podrás ver tú.

La magia del .gitignore

La carpeta "/Assets/ClassResources/Students" está incluída en el archivo .gitignore, esto hace que git ignore por completo los cambios que ocurren dentro de esa carpeta. Esto nos viene de perlas porque no queremos que git detecte tus cambios hechos, si no, al actualizar el proyecto, tendrías que subir tus cambios lo que puede llevar a conflictos dentro del proyecto con tus compañeros, cosa que no queremos que pase.

¿Qué pasa si trabajo fuera de mi carpeta?

Esto es algo que puede pasar sin darte cuenta y es completamente normal. Git detectará tus modificaciones y podrás verlos abriendo GitHub Desktop a la izquierda, en la ventana "Changes", habrá una lista con todos los cambios que se hayan detectado. Si has trabajado de manera correcta, en tu carpeta, estará vacía.

Para llevar el trabajo realizado a tu carpeta pero no modificar el proyecto sigue estos pasos:

  • 1. Observa en la lista de cambios los archivos que has moficado y búscalos dentro del proyecto de Unity
  • 2. Haz una copia de esos archivos y guardalos en tu carpeta. Asegurate de que están guardados en tu carpeta.
  • 3. Ve a github desktop y en la ventana "Changes" a la izquierda, haz clic derecho en " changed files" y luego "discard changes" para eliminar los cambios.

Con estos pasos tendrás tu trabajo guardado en local sin modificar el proyecto en el caso de que hayas moficado archivos originales del proyecto.

3. Exportar el trabajo y entregar

La primera entrega de la asignatura consiste en entregar un script creado dentro de tu carpeta "Scripts" para comprobar que has entendido todo este proceso. Para ello vas a exporarlo como ".unitypackage".

  • 1. Crea el script haciendo clic derecho en tu carpeta "Scritps". Da igual el tipo de Script para esta tarea. Ponle de nombre "entrega-1".
  • 2. Asegúrate de que lo has guardado en el sitio correcto.
  • 3. Para exportarlo, pulsa clic derecho al asset que quieras exportar, en este caso tu script que acabas de crear, luego pulsa "Export as Asset Package...".
  • 4. Se abrirá la ventana "Exporting package". Por defecto vienen todos los scripts incluídos, procura desactivar la opción "include all scripts". Las dependencias son necesarias en caso de que lo que vayas a exportar dependa de otros assets, para esta entrega, solo debe aparecer el script en tu carpeta. Pulsa "Export..."
  • 5. Busca una ruta para guardar tu ".unitypackage". Ese es el archivo que debes entregar en la entrega del campus virtual.
